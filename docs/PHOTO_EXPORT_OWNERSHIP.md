# Photo export owns its editor session and destination work

Zero new user-facing features; one core export correctness fix. This does not add another photo export workflow.

A chosen native photo export now keeps an immutable edit/source/destination/scope/access-mode/foreground-generation/format/quality/protected-original snapshot. It renders from that snapshot rather than live settings. Editor Undo can change current work without changing the chosen export edit. Foreground/source/session changes, a different pending export snapshot or replacement operation invalidate work; pause/destroy explicitly cancels the operation. Export admission also remains busy independently of the pending-edit field.

Pending picker results received while paused wait for foreground/source/recovery readiness. The original generation starts only after that readiness; current-scope checks guard dispatch and worker phases. Completion can clear busy/pending state only for its own current operation. A stale completion cannot release another job. Current-context notices distinguish success, failure, memory pressure and interrupted work; a background completion keeps its notice for a matching foreground editor. An interrupted operation can already have completed a copy, so the message asks the user to check Files.

SafePhotoCopy retains URI/inode alias checks for the source and every protected original. Its new optional guard runs before native destination access/truncation, around private encoding and sync, during source/destination digest reads, before bounded256KiB copy writes, and before final validation. Originals stay open until the destination is checked/written/validated, and temporary encoding files are removed in finally. Stream helpers handle zero-length reads and propagate read/write/cancellation failures while callers own closure. JPEG flattening/quality, PNG encoding, byte-digest and MIME/dimension checks are retained.

This is cooperative cancellation, not an atomic output transaction. Bitmap encoding/native calls already executing cannot be interrupted immediately, and destination access or truncation can precede cancellation. An empty, partial or completed document can remain. The app never deletes or blindly restores a potentially user-owned destination on failure. There is no guarantee against every provider race or native crash. Permission/owner checks during bounded chunks may add overhead; device performance is unmeasured. No personal media, queries or test fixtures were uploaded.
