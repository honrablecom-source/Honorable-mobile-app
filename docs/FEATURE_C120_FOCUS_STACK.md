# C120 — Aligned focus-bracket stack

Library → Select originals → Create aligned focus stack accepts two to five already aligned focus-bracket photos. Explicit Prepare selects locally sharper regions into a separate PNG preview; explicit Open transfers that PNG into the existing guest photo workspace. Every original is read-only and passes through the existing protected-original save/export URI contract. No media or queries are uploaded.

For each frame, encoded RGB becomes rounded integer luma (77/150/29 weights), premultiplied by alpha. A four-neighbor absolute Laplacian with clamped borders estimates high-frequency contrast. Its clipped five-by-five neighborhood sum is compared at each coordinate. The highest score selects the actual source pixel; ties use selection order. Summed-area computation bounds work to linear time per frame. Source alpha and colors are copied exactly; hidden transparent RGB cannot generate contrast. The largest allowed integral sum is below signed-Int range. This is focus selection rather than temporal outlier removal: complementary sharp regions can come from different input frames.

There is no automatic alignment, depth inference, blending or guarantee of an all-in-focus reconstruction. Noise can win the contrast test; movement, exposure changes and focus breathing can cause wrong selections and visible seams. The review explains these limits before reads. Already aligned steady-camera captures with differing focus are needed. At most1024pixels per edge are decoded into the common sampled grid; fine detail can be lost. Readable EXIF orientation is applied, otherwise upright fallback; animated formats use the first decoded image. Corrected source dimensions must match before pixel decoding; decoder rounding uses nearest-neighbor normalization.

Shared decoder limits:32768source-edge/100million source pixels,96MiB free-JVM-headroom admission,64MiB per read stream/256MiB total, checked60-second deadline and16MiB private PNG output cap. Blocked providers/native decoders can delay cancellation. The shared lease/request/foreground/account/source guards revalidate before staging and opening. Close/background/unmount/source or account changes remove staged output; late replies release their own token. Native response operation and frame count must match the review. Opening is an explicit ownership transfer; late release cannot delete the editor's source. Existing Save/project actions are needed to retain the derived output.
