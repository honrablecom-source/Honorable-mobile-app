# C114 — Private recorded-original integrity baselines

Library → Private integrity baselines records1–20 selected originals under a new name, then verifies that saved set later without requiring a current selection. Recording reads actual source bytes natively and saves only after every selected original finishes with a valid SHA-256/length fingerprint. The shelf keeps up to10 baselines per account on this device. It stores original ID/URI/type, bounded display label, recorded byte count/hash and recording time; it never stores media bytes or sends them over the network.

Verification compares the current bytes of each saved exact identity with its recorded fingerprint. Results separately identify matching/changed bytes, missing/reused identities, unreadable sources, read limits and changed provider length. Missing references are not opened and never substituted with another file. A verification has exactly one accounted result per recorded original; it cannot silently omit failures. Its report preserves recorded labels for identification. Verification never updates recorded hashes or writes the baseline record.

The existing bounded reader is reused with an explicit one-original minimum for this workflow; duplicate comparison keeps its two-original minimum. Reads retain256MiB/file,512MiB total,60-second checked deadline and64KiB buffer bounds, current account/foreground/source guards and owned provider/stream cancellation. Reaching a read limit before EOF is confirmed skips the file. Baselines are not locked file snapshots or backups; results concern delivered bytes and known-length mismatches. A blocked provider can delay cancellation/deadline response. Saving records may already have committed when Cancel arrives; cancellation does not promise rollback.

Names, source bindings and fingerprints are bounded and validated by immutable models. A versioned binary codec binds its owner; a separate owner-hashed record reuses existing Android Keystore/AtomicFile encryption and preserving reads. Wrong-owner, corrupt, truncated, trailing, over-limit or incompatible records refuse without resetting data. New saves merge latest state under a lock and never overwrite an existing name/ID. Fresh source/account admission precedes writes. Verification also rechecks current catalog availability and the exact saved baseline before reporting, refusing a removed or changed baseline. Removal has a separate explicit review and deletes only the chosen metadata, with no Undo.

The white mobile shelf supports recording, verification reports, retry, cancellation and reviewed removal. It does not read metadata automatically. Account changes, backgrounding, closing and unmount invalidate pending outputs and clear private data. Exact shelf/request/view ownership refuses old rows and prevents retained Cancel callbacks from dismissing successors. Native replies with the wrong owner cannot replace visible data. A shared synchronous Library admission guard excludes collection, duplicate and integrity operations before React updates disabled state.
