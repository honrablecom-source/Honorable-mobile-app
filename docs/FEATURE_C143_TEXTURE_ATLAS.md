# C143 — Texture atlas with a bound coordinate map

A distinct source workflow: Photo tools → Texture atlas packs two to six distinct embedded photos into one exact-size PNG plus a coordinate map. Registered as source139/500 after final source/browser verification. **1 new source workflow;0 separate fixes;0 scaffolding.** This is not a native APK/device claim.

## Result and scope

The user selects embedded photos, chooses an8–1024pixel output grid and0–16pixel gutter, reviews the PNG and JSON, then inserts the exact PNG and map as one separate image object or explicitly hands only the exact PNG to the photo editor. A manually selectable JSON field supports the device text-copy menu. The map is Noble's own format, with top-left pixel-edge rectangles, normalized UV edges, anonymous frame labels, source-copy SHA-256 bindings and the exact atlas PNG SHA-256. It is not an engine-specific importer; receiving renderers may need vertical-coordinate/filtering adaptation.

Original pixel dimensions are preserved before canvas crop/rotation/flip/opacity. No scaling, trimming or rotation occurs. The original deterministic guillotine packer sorts by maximum padded side/area/input order, chooses the smallest fitting free area with stable ties, and partitions remaining space into disjoint rectangles. It does not promise an optimal packing or that every mathematically possible fit will be found. Nearest-edge source RGBA is extruded through each gutter; unused space is transparent. Empty sources as a group and invalid/nonfitting grids are refused. Exact PNG output above192KiB is refused without smaller substitution.

Insertion stores the coordinate map in the new image's customData. Reopening Texture atlas on that image rederives and validates the saved packing and exact PNG binding before displaying the map. OneUndo removes image+map; Redo/reload and portable projectJSON retain both. SVG and exact PNG handoff retain the image; copy the separate map before PNG-only handoff. All source bytes/geometry remain separate and unchanged. Exact-source/frame labels are anonymous; there are no personal filenames or queries in the map.

## Implementation and invariants

`photo-atlas.mjs` contains packing, RGBA extrusion and untrusted saved-map validation. `photo-atlas-task.mjs` validates source buffers and returned frame/size/gutter/binding/buffer/visible-count metadata around an owned single-use local Blob worker. Source arrays are privately copied before transfer, workers terminate and Blob URLs revoke on success/failure/abort/deadline. A30second overall decode/worker/PNG lifetime, hidden-document cancellation, sticky scene ownership, Escape/Stop and exact-PNG admission preserve original protection. Decoding is sequential and successful packing bounds total source pixels by the≤1024square output. Source content hashes are checked against actual embedded bytes. No network/dependency or native permission was added.

`PhotoAtlasTool.jsx`, PhotoObjectTools/editor integration and the existing exact PNG insertion/handoff path provide review and recovery. Source-selection labels have44pixel touch heights. The existing generic insertion hook only attaches known owned atlas customData before the same capacity checks/atomic scene publication; it does not bypass source checks or create a second history operation.
