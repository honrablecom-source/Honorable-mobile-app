# C162 — Reviewed video frame-sequence archive

1 new experimental source workflow; 0 separate product fixes; 0 product scaffolding. Source/API and focused checks passed; native runtime and device acceptance remain unverified.

Video Project → Export frame sequence archive prepares 4, 8 or 16 nearest source-frame PNGs from the selected clip's visible source range. It reviews every complete PNG with its requested time, size and checksum, and the complete manifest, before an explicit Share reviewed ZIP action. The archive is a portable collection of independent images, unlike C160's single time-slice composite, the flattened storyboard, or the original-media ZIP.

Each PNG is at most 512 pixels per edge without upscaling, 2 MiB encoded; all PNGs at most 16 MiB and the ZIP at most 20 MiB. The manifest records version, source selection boundaries, nearest-frame/SDR limitations and each frame's generated name, requested source milliseconds, dimensions, encoded byte count and SHA-256. It does not include original URI/filename, account or project metadata. Decoded source image content and selected timing are deliberately exported and disclosed before sharing. Actual decoded timestamps are unavailable; nearby samples can repeat and nearest frames can fall outside very short requested windows. Video effects/captions/grade/crop/motion are excluded. No HDR, profile, exact frame timing or external-app compatibility claim.

The background worker uses the existing account namespace guard and a checked 60-second deadline. Provider/decoder blocking can delay physical cancellation; late results are disposed. Whole archive and each entry are checked before previews and again before sharing. Preview bitmaps come from the actual prepared ZIP. Invalid signature/geometry, changed dimensions, oversized PNG/aggregate/archive, source duration changes, decoder failure, stale owner/session and cancellation refuse output and delete partial files. Old files from this workflow alone can expire after a day. No original/timeline mutation or account privilege transfer. Original identity uses URI/duration/session scope, not a media-byte fingerprint.

The existing one-use lease disposes replaced/cancelled exports. Sharing takes ownership before opening the Android chooser, so onPause cannot delete the handed-off file. Only a read grant for the generated ZIP is supplied through FileProvider and ClipData. Choosing a destination app is explicit; Noble does not automatically upload anything. A chosen app can retain copies. Cancelling its chooser is not a delivery success claim, and the temporary export must be saved there to keep it.
