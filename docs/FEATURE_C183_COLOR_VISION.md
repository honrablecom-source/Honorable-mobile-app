# C183 — Comparative color-vision proof sheet

One new source workflow: Photo tools → Create from this photo → Color-vision proof sheet prepares an opaque original composite and protan/deutan/tritan simulations together. Review every PNG, hand off an exact selected PNG, or insert all four labeled images as one group with one Undo. Four views are parts of one comparison outcome, not four feature counts. No separate product fixes or scaffolding counted.

## Encoding and scope

`photo-vision.mjs` privately captures an 8–1024-pixel source on each axis. It composites source alpha over the selected opaque #RRGGBB backdrop in encoded sRGB, rounds to eight bits, then decodes the composite with the piecewise sRGB transfer function. Three published severity-1 matrices transform linear RGB; each linear channel is clamped to [0,1] before encoding and rounding to eight-bit sRGB. The reference view is the same opaque composite before simulation. Transparent hidden RGB cannot affect output; the backdrop is simulated too. Full embedded source precedes canvas crop/rotation/flip/opacity. No ranking, native search, credits, ledger or media uploads changed.

Matrix reference: [Machado, Oliveira and Fernandes author-hosted model and severity table](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html). All 27 severity-1 coefficients independently checked against the downloaded author table; retained research HTML and SHA receipt under `.context/noble-fast-web/c183-research/`. The web reader timed out; curl retrieved the primary page successfully. No third-party implementation copied. Our alpha/encoding/clamping policy is explicit above.

These are design-proof approximations, not a diagnosis, accessibility certification, display calibration or guarantee of an individual's vision. Natural-image usefulness, HDR, display profiles, printing and medical interpretation are unverified.

`photo-vision-image.mjs` uses a shared 30-second deadline, current/visibility/abort checks and sequential exact-grid encodes. All four opaque PNGs must fit 192 KiB each; any failure refuses the whole operation without resizing or dropping views. Every canvas/image handler is cleaned up. Private source plus four output planes use at least 20 MiB at maximum size, with additional decode/canvas/PNG overhead; phone memory/performance unverified.

`PhotoVisionTool.jsx` provides backdrop input, four complete previews, exact selected-PNG retry and atomic insertion. Every image records model, severity, backdrop, source file ID, original dimensions and encoding convention `noble-vision-srgb-v1`. Identical PNG content can share a file ID while preserving all four image roles. Eight-object group insertion checks existing eight-photo/500-object/storage limits; original source bytes/geometry stay unchanged. Any scene edit permanently revokes approval even when followed by Undo. Stop, hidden page, Escape, late bitmap verification and unmount cancel ownership.
