# C122 — Split at pasted edited-playback times

Native video Project tools → Split at pasted playback times accepts1–100 strictly increasing timestamps in decimal seconds or HH:MM:SS.mmm (up to three decimal places). Times refer to edited playback after clip speed changes, across every source/clip. This creates cuts without removing, duplicating or reordering footage. It is distinct from C103's source-range shot list, equal division and manual tempo grids.

The input is reviewed before applying: requested playback time, actual source-millisecond-quantized playback time, original clip/source ID and source timestamp for every new cut. Existing exact clip boundaries are retained and counted; a proposal containing only those boundaries is refused as a no-op. Input excludes zero, the project end, outside times, duplicates, reverse order, invalid syntax and over-limit text/rows. Source timing uses existing supported Int millisecond bounds. New pieces must have at least0.1 playback second after source rounding; no tiny pieces or duplicate rounded source points are silently accepted. Unsplit clips retain their original objects and may already be shorter.

Each source interval is partitioned into contiguous ranges with the same initial start, final end and complete coverage. Speed, source, volume, titles, color, framing, motion and audio settings remain copied. Source-anchored captions intersecting a piece retain their timestamps and subtitle-document provenance; a crossing cue remains on both pieces, a touching cue only on its side. Edge/audio fades repeat on new pieces and can change rendered output. Codec frame-exact cuts are not promised. Floor rounding of each piece can change total playback length by microseconds; the exact difference is shown. Soundtrack settings remain unchanged; preview before export.

The proposal uses existing VideoBatchReview ownership and full session/source/review gates. Input opens only after capture/admission. Only the current visible tracked stage can advance; replacement/hidden/paused/foreign/stale callbacks cannot approve. The exact project object is rechecked before commit. Applying consumes the immutable one-use proposal and invokes the real project validator once; Undo restores the whole prior timeline/soundtrack. Caption/count/title/recovery bounds are checked before review and again at project application. Cancellation clears the pasted text. No clipboard, media upload, original write or new permission is involved.
