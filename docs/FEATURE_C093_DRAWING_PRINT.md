# C093 — Print drawing artwork or save it as a PDF

**1 new experimental source workflow; 0 separate fixes; 0 scaffolding.** The source register advances91→92/500, batch54 beyond38. Full native/APK build and physical-device acceptance remain pending. Whole/selected controls and PDF/printer destinations are one output workflow, not separate features.

In drawing Projects → Print or PDF, choose the whole visible drawing or the currently selected artwork. Attached labels/frame contents accompany a selection; hidden/deleted artwork and unrelated photo copies are excluded through the existing detached image export. A white-background PNG snapshot, up to2048pixels and8MiB, is transferred in bounded32Ki-character chunks. The editable scene and saved draft stay unchanged.

Android's print sheet lets the user review paper, orientation, margins and destination, including Save as PDF. The adapter fits and centers one flattened image without cropping, using the content-sized recording canvas rather than adding page margins twice. Output is not vector PDF; large prints can look soft. Requested monochrome output materializes a separate gray bitmap because PDF canvases do not support Paint color filters. The default keeps artwork colors. See [Android custom printing](https://developer.android.com/training/printing/custom-docs), [PrintedPdfDocument](https://developer.android.com/reference/android/print/pdf/PrintedPdfDocument), and the [AOSP recording/output coordinate implementation](https://android.googlesource.com/platform/frameworks/base/+/35aacf2/core/jni/android/graphics/pdf/PdfDocument.cpp). These sources guide implementation, not device acceptance.

Only an explicit print action invokes the OS sheet. Native code writes solely to the print framework's provided spool descriptor; it never opens a media/destination URI for writing. App code adds no network upload; final output follows the user's chosen Android print service. A closed dialog is reported as closed, with instructions to check print status or the saved PDF. It does not claim saving, printing or delivery succeeded.

## Ownership and failure behavior

Import/export/print admission uses a shared native lock. Only the admitted request owns its chunks/release; malformed, inactive, closed and busy requests are refused. Duplicate preparation cannot mutate or prepare a second snapshot. MIME/payload/header/decoded-size validation precedes handoff. Leaving the foreground cancels preparation before the OS sheet opens; an already-open sheet owns its session. Activity destruction cancels that session, and recreation shows an interruption label without replaying image bytes or automatically printing again.

The print adapter uses a worker, immutable image, layout-generation checks, cancellation-aware bounded32MiB output and ordered bitmap cleanup after active writing. Page0 is the only requested page rendered. Closing/cancellation may leave partial framework spool data; no rollback or external-delivery guarantee is added. Widget/provider/OS lifecycle behavior remains unexecuted.

The web side validates the document before handing off its immutable snapshot. Later viewport/selection changes cannot retarget captured artwork; document edits invalidate preparation. Print result IDs must match the pending request. All controls remain busy until the native response and the renderer has left read-only mode; the exact selection is restored without Undo only if the editor/document is still current.
