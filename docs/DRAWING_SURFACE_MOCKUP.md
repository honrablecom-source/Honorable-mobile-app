# Surface mockup — C102

Drawing → Objects → Surface mockup places one embedded photo onto a flat four-corner surface in another photo. Choose the artwork, mark the background surface clockwise, preview, then insert a separate flattened PNG beside the background. Both source objects and their embedded bytes remain unchanged. Undo removes the new copy; saved drafts, reload, portable project JSON and selected-artwork image export retain it.

This is one new source outcome. Corner selection, transparency, opacity and coordinate entry are parts of the workflow, not additional features. Existing photo straightening creates a rectified image from one source, and the native perspective-poster effect pinches a single image; neither provides this two-source surface composition.

## Behavior and limits

Both sources use their full embedded PNG/JPEG before drawing crop, rotation, flip or opacity. The interface discloses this before placement. Artwork stretches to the chosen quadrilateral; its transparent areas reveal the background. Lower artwork opacity blends the result. This is a flat-surface mockup, without automatic lighting, occlusion, reflections or curved-surface modeling. Placement is flattened after insertion; keep both originals to try another surface.

Sources are bounded by existing stored-photo limits: 192 KiB each and 8–1024 pixels per side. Surface points are finite photo-boundary coordinates inside the background, form a clockwise convex quadrilateral, stay at least two pixels apart and cover at least 16 photo pixels. Invalid, concave, crossed, repeated, reversed, too-small or numerically unstable geometry is refused. Opacity must be above zero and at most 100%. Invisible artwork and unchanged results do not claim an edit.

The already pinned MIT `perspective-transform` 1.1.3 package supplies the inverse homography. No new dependency is added. Four subpixel samples combine geometric coverage and premultiplied bilinear color before source-over composition. Hidden artwork RGB cannot tint visible edges. Aligned one-to-one integer placement preserves each artwork pixel without filtering blur. The background remains byte-exact outside the marked surface; both input buffers remain unmodified. Other placements resample pixels and may soften detail.

The image wrapper snapshots geometry before asynchronous decoding, validates both embedded sources before making decoder requests, checks dimensions and releases image handlers/canvas storage. Preview processing yields every eight rows and checks the current document/source lifetime. Cancel, close/unmount, a hidden page, decode/encode errors and a 30-second deadline refuse publication. The deadline is cooperative with the browser event loop, not an interrupt for blocked native decoding. Preview Blob URLs are revoked when replaced or closed.

Insertion reuses the guarded local-photo preparation and durable scene publication path. It checks both source bytes, the captured draft and component lifetime throughout preparation. A latched document change cannot revive through Undo. Cancel remains reachable while actual output-bitmap preparation is pending; the editor stays busy until that work releases its owner. Object count, encoded-draft size and storage quota checks occur before scene mutation. Output may shrink to fit local storage.
