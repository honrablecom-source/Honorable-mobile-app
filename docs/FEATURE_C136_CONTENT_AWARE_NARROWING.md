# C136 — Content-aware photo narrowing

Library → Select originals → Create content-aware narrowed photo reviews one original and a whole1–12percent narrowing amount. Explicit Prepare removes connected vertical seams into a separate PNG preview; explicit Open transfers it into the existing local photo workspace. This changes composition by removing low-gradient paths rather than uniformly scaling or cutting a rectangular crop. It can distort a subject or remove important content; there is no subject recognition/protection guarantee. The original is never edited or uploaded and remains protected through the existing original-URI save/export contract.

Processing uses the existing readable-EXIF-corrected decoded grid, at most1024pixels per edge, with nearest-neighbor normalization of decoder rounding. Animated formats use their first decoded image. The percentage applies to that grid's width and rounds upward to whole columns, at least one; height stays fixed and at least one column remains. The native kernel bounds removal to128columns; the exposed1–12percent policy needs at most123on a1024wide grid. Review reports actual output/source/decoded dimensions, removed-column count and source sampling status. The default10percent survives review opening/closing; invalid values cause no private read.

For each removal, energy sums clamped horizontal/vertical absolute alpha and premultiplied-RGB differences. Dynamic programming finds a minimum-energy eight-connected vertical path, with stable leftmost predecessor/bottom ties. Source rows are compacted in private scratch storage; energy is recomputed on the new grid. Remaining raw decoded ARGB values keep row order and no new colors are synthesized in the pure kernel. Parents/cost/row storage is bounded and reused. Cancellation is checked before allocation, per path row and row compaction. Platform Bitmap/color/PNG conversion may affect exported pixels and is not device-verified.

The shared native read pipeline retains64MiB per-stream/256MiB total budgets, source metadata limits,96MiB free-JVM-headroom admission, a checked60second processing deadline and16MiB staged PNG limit. Blocked provider/native decode calls can delay cancellation. Output dimensions use the actual carved width; decoding-sample status uses the original decoder plan rather than mistaking narrowing for source downsampling. Current account/foreground/exact source bindings are rechecked. One-use preview leases, owned cancellation and protected guest-editor handoff are reused; stale replies/Cancel/image errors cannot clear a successor. Close/background/unmount/owner or source changes drop staged output. Transferred editor sources survive late release.
