# C138 — Keep a whole-timeline playback excerpt

Native video Project tools → Keep playback excerpt accepts a start/end in edited playback seconds, after clip speed changes. The interval can cross existing cuts and source videos. Review shows every retained source window and its original playback position, current/new clip count and exact playback duration. Apply replaces the timeline with those pieces in order as one Undo step; original files are never cut, overwritten or uploaded.

Fully retained interior clips remain unchanged, including existing very short clips. Partial outer pieces round source starts upward and ends downward to whole source milliseconds; each newly trimmed piece must retain at least0.1playback second after rounding. No tiny edge piece is silently dropped. If the requested end is the ceiling millisecond of a fractional project end, it clips to the true end rather than losing the original final source millisecond. Outside/reversed/invalid/whole-timeline no-op proposals are refused. Source/project timestamp bounds use the existing Int millisecond policy.

Intersecting captions retain their original source timestamps and subtitle-document binding; captions outside a partial kept range are removed. Source-anchored motion, title/style, grade, framing, fades and source-audio settings stay. Fades repeat at newly trimmed edges and may change the result. Soundtrack settings are retained and music restarts from its current source excerpt at the new timeline beginning; this does not preserve its prior playback offset or produce a bit-identical rendered movie excerpt. Preview/listen before export. Codec frame-exact cuts are not promised.

Input/review stages reuse current visible VideoBatchReview ownership and full foreground/session/source/project snapshot guards. Exact project identity is checked again before one-use Apply. The actual project validator and Undo/Redo authority retain soundtrack and original document protection; source catalog and permissions are not changed. Cancel/dismiss clears inputs and review text. The proposal is metadata-only; decoding/rendering stays in existing preview/export paths.
