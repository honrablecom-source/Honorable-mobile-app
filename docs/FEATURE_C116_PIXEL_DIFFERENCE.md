# C116 — Two-original decoded pixel-difference maps

Library → Select originals → Create photo pixel-difference map reviews two selected photo originals and a0–255 whole-number threshold. Explicit Prepare creates a separate opaque black-and-white PNG preview; explicit Open map as separate photo transfers it into the existing local guest photo workspace. It does not replace either selected original, edit the Library or upload any media. Both originals are passed through the existing `ImportedPhotoOriginals.EXTRA` protection contract for subsequent export/save-copy alias checks.

The source photos must have equal orientation-corrected dimensions. Readable EXIF orientation is applied; unsupported/unreadable orientation metadata defaults upright. Animated formats use the decoder's first image. There is no automatic registration, crop or alignment. The common grid uses a power-of-two decoder sample with at most1024pixels per edge/1,048,576cells; decoder rounding is normalized with nearest-neighbor sampling. Source bounds are limited to32768pixels per edge/100million pixels before decode, with a64MiB free-JVM-headroom admission check. Compression, color/decoder conversions and sampling can produce differences. This is sampled decoded-pixel analysis, not original-byte or perceptual identity verification.

For each cell, RGB is premultiplied by alpha with integer rounding. Delta is the maximum absolute difference across alpha and the three premultiplied channels. The output is opaque white when delta exceeds the chosen threshold and opaque black otherwise. Hidden RGB beneath fully transparent pixels is ignored. Changed-cell count follows the threshold; maximum/mean delta report raw values, including ignored differences. The threshold and sampling statistics are shown with the actual preview. All threshold values belong to this one workflow.

Reads share a64MiB per-stream/256MiB total budget and a checked60-second deadline across bounds, EXIF and decode passes. A production pure-JVM wrapper bounds block/single reads, conservative availability and skip-by-reading; it preserves errors/limit exhaustion even when a decoder swallows an exception. Unsupported reset, repeated no-progress reads and provider errors cannot yield a successful completed decode. Cancellation closes current IO and requests provider cancellation. A blocked provider or native decoder may delay checks; there is no hard wall-time guarantee. Only read mode is used for sources.

The output is a fresh bounded private PNG under the existing canonical `created-images` cache, with fsync and16MiB output limit. Partial/cancelled output is deleted. A native one-use preview lease replaces/releases only owned tokens and clears on pause/destroy/module invalidation. Workspace opening consumes the lease before launching, rechecks foreground/account/exact source identity and honors cancellation immediately before launch. Failed opening disposes the consumed preview. After successful transfer, a later Close/release cannot delete the editor's source. The derived image is temporary until kept through existing photo Save/project flows.

The React sheet reads nothing on opening, renders no image before preparation and displays only the returned derived PNG. Owner/selection changes, backgrounding, closing and unmount cancel work, release staged artifacts and clear private preview state. Late replies release their own returned token. A stale image error or Cancel cannot clear a successor. Threshold edits discard old previews. Shared synchronous parent admission prevents competing Library work before disabled state renders. Opening a workspace is an explicit committed action and cannot be recalled after launch.
