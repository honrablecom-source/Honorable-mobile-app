# Drawing photo import ownership

November 7: **0 new user-facing features; 1 correctness integration fix; 0 app scaffolding.** Shared source count remains 95/500, batch 57 at this checkpoint.

Photo picker metadata now belongs to one native operation. Matching results are consumed once, waiting for foreground before copy work begins. The expected pause caused by the picker retains the unanswered selection. Started copying and ready deliveries cancel on pause; old queued workers cannot access the provider or release another operation. Recreation stores only an interruption Boolean and shows retry guidance; no URI or photo payload was added to saved state. Existing selected-content/read-only intent, 1024-edge/192KiB copy bounds, decoder/orientation/metadata removal and original protection remain unchanged.

The new opt-in chooser retains its import lease through asynchronous canvas preparation. Native exposes current/release checks; the current editor uses them before decoding/accepting/committing the copy and releases only its admitted attempt. A success already queued when the lease is cancelled is rejected before decode. Cancellation while bitmap preparation is pending keeps that attempt busy until its cleanup completes, preventing the old finally block from clearing newer work. Duplicate success while applying is ignored. An orphan photo cancellation cannot unlock a print operation. Failed admission never releases a native lease it did not acquire.

Compatibility is explicit: the old chooser still releases native admission before delivery, so older bundled clients do not need the new acknowledgement. Current web code falls back to that old chooser when the complete lease API is absent. The additional native lease checks apply to the opted-in path; older native clients cannot supply them. The complete current native and drawing assets must be packaged together at the agreed build batch.
