# C118 — Aligned burst clean plate

Library → Select originals → Create aligned-burst clean plate reviews three or five selected photos, explicitly prepares a separate PNG, then explicitly opens that PNG in the existing local photo workspace. Opening the review does not read photos. Originals remain read-only and every original URI enters the existing protected-original export contract. No uploads or remote processing.

Use steady-camera, already aligned captures with equal orientation-corrected dimensions. At each sampled position, the kernel finds component medians of premultiplied RGB and alpha, then chooses the actual input pixel with the smallest total channel distance. Ties use selection order. This preserves source colors, including identical semitransparent pixels, rather than synthesizing an average. A transient object can disappear when background pixels dominate that position; persistent objects remain. Camera movement, changing light, compression and motion can produce artifacts. This does not perform registration or recognize objects. Three versus five frames are parameters of one workflow.

The preview reports sampled/source dimensions, capture count and cells differing from the first capture. The shared decoder applies readable EXIF orientation, uses the first decoded image of animations and normalizes rounding through nearest-neighbor sampling. All originals must have matching corrected dimensions before decoding pixel arrays. The shared power-of-two grid is at most1024 pixels per edge. Admission requires96MiB free JVM headroom; each source remains subject to32768-edge/100million-pixel metadata limits. Shared read budgets are64MiB per stream and256MiB total, with a checked60-second deadline. A blocked provider or native decode may delay cancellation.

C116's bounded read wrapper, fresh private created-images PNG (16MiB limit), one-use token lease and protected guest photo opening are reused. The native request slot prevents competing Library reads; foreground/account/exact-source identity is rechecked. Close/background/source or account change/unmount cancels work and releases staged files; late results release their own token. Successful workspace opening transfers ownership so late release cannot delete its source. Derived output is temporary until kept through existing Save/project flows. Response operation/capture count is checked before rendering; source images are never shown as the result.
