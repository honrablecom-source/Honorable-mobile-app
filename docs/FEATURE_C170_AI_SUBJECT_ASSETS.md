# C170 — AI individual-subject asset pack

**1 new experimental AI source workflow;0 separate completed product fixes/scaffolding.** Photo editor → On-device AI → Subject asset pack detects individual foreground regions, previews their transparent cutouts, selects none by default, then reviews/exports only chosen PNGs and a checksum/provenance manifest as one ZIP. Original media/current photo edit are unchanged. Real SDK/model setup/device/quality acceptance remains open; this is source/API/Robolectric acceptance, not a shipping claim.

This uses the actual ML Kit Subject Segmentation SDK's multiple-subject confidence masks. It does not fabricate detections, name objects, identify people or generate missing pixels. The old person-union cutout/background tool remains unchanged. C151 splits already-transparent alpha islands (an opaque photo is one island); C101 needs manual outlines. This new outcome separates and curates estimated foreground subjects from an opaque photograph, including non-person regions, as reusable assets. Subject IDs are only positions in this batch, not persistent identities. Nearby/touching subjects can merge; edges/faint pixels can retain background. It is not privacy redaction or pixel-perfect matting.

Workflow and ownership:

- Entry requires current guest/account editing scope, foreground, settled edited preview and no competing work/recovery/export. The shared full photo raster path freezes current edits; a separate owned bitmap is fitted to at most1024pixels per edge. Opaque previews only, no original-resolution promise. The current edit and source byte files are not mutated.
- Model setup/diagnostics consent starts unchecked. The real adapter checks compatible Google Play services and module availability; only explicit setup permits an installation request. It rechecks actual readiness before calling the real segmenter. No install-time subject-model metadata was added (including in the actual SDK AAR). Images are processed on-device; SDK diagnostics/model download use Google services. A download/in-flight inference may finish after Stop. Unsupported Google Play services produce a clear error; no fake fallback mask.
- Result masks are copied into bounded owned values. Up to12subjects and4,194,304total mask pixels; every geometry/confidence must fit the captured grid and be finite in0–1. No silent truncation. Source-aligned crop colors get rounded confidence alpha; alpha-zero output is canonical zero RGB. Each PNG's own decoded bytes are previewed on a checkerboard; selections start empty. The final page shows every selected image, dimensions/bytes/SHA, positions, grid fingerprint and ZIP SHA before a separate share action.
- The PNG validator checks CRC, supported8bit truecolor format/dimensions, no original EXIF/text chunks, bounded zlib data/row filters/exact inflated size. Limits5MiB per PNG,32MiB total PNG bytes and32MiB+65536ZIP bytes. Selected IDs are unique/canonical; each captured asset binds to the same source-grid SHA. Changed PNGs/ZIPs, malformed images, empty selection, overflow, cancel or owner changes fail closed. Whole ZIP hashing and payload verification stream bounded buffers.
- Files are private cache artifacts until an explicit one-use read-only ZIP grant. Transfer happens before the chooser pauses the Activity; all unshared PNG/ZIP stages are cleaned. A receiving app can retain chosen images and the manifest. Shared cache copies may expire after a day; save through the chosen app. The full original photo file/name/URI/EXIF is omitted, but selected cutouts can include faint background detail and the manifest includes the working-grid fingerprint. Exact current account/project/generation/foreground guards protect callbacks/handoff. SDK-owned bitmap/client cleanup waits for task completion, including after cancellation.
