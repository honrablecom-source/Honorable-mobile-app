# C092 — Arrange selected photo objects by their centers

One experimental source workflow: explicitly select several eligible native photo objects, review a shared center arrangement, and apply it as one Undo step. Existing photo controls positioned objects individually. Alignment and spacing choices are parameters of this one outcome, not separately counted features.

Open **Photo inspector → Composition objects → Arrange selected objects**. Choose at least two visible, unlocked, nontransparent objects. Pick a vertical column (same horizontal center), horizontal row (same vertical center), or evenly spaced centers left-to-right/top-to-bottom. Spacing requires at least three selected objects. A review lists every changed position and the number moved before explicit Apply. Back returns to arrangement/selection; invalid or unchanged arrangements display a visible notice and preserve all edits.

Alignment uses the midpoint between the selected outer centers on the chosen axis. Spacing sorts existing centers along that axis, with original layer order breaking ties, and keeps the outer centers fixed. The orthogonal coordinate, size, rotation, text/style/color/opacity and layer order remain unchanged. Hidden, transparent, locked and unselected objects keep their values/identities. Geometry is output-relative center placement: this does not measure rotated edges, glyph ink, edge gaps, overlap or clipping. The review tells users to check those visually.

Preparation validates 2–32 unique known eligible IDs, with three or more required for spacing, then creates a bounded immutable plan. Original model validation still enforces finite center coordinates in 0–1. No-op plans retain the same model and add no Undo entry. The Activity commits only a changed plan prepared from its exact current model under the current controller/full photo snapshot/scope/access mode/foreground/generation. One existing Undo/Redo restores all positions while original-source protection remains. Pause/destroy closes the controller; replaced selection/action/review callbacks cannot approve or close a later owned dialog. Text-replacement and arrangement admission share the same metadata-review guard, while existing entry method contracts remain covered by retained tests.
