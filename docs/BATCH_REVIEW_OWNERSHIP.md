Each batch request owns one current dialog stage, and only that exact request/dialog, tracked and showing in a current foreground snapshot, can advance or apply.

VideoBatchReview freezes the original segments/captions and soundtrack, accepts one frozen proposal per stage and drops any previous proposal on stage advance. Showing a successor opens/assigns it before dismissing its predecessor; a late dismissal or callback from an old stage cannot close the current one. Options, both text-input paths, tempo then beat selection, and final review all use this protocol. Text fields are dropped on dismissal. The final approval consumes its proposal before checking current context and applying, including on failure; Undo cannot revive it. A stale callback from a different stage/request cannot consume a newer owner's approval. Pause/destroy review invalidation closes the request even when no Android dialog callback is delivered.
