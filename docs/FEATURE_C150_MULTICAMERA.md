# C150 — Manually synchronized camera-switch edit

**1 new experimental source workflow; 0 separate fixes; 0 scaffolding. Registered after verified source checks.** Video Project → Build camera-switch edit takes per-camera matching-event anchors and an ordered program-clock switch list, derives exact original-source windows, reviews every calibration/window and replaces the timeline only after explicit Apply and preview. One Undo restores the prior timeline. It does not read media, upload anything or automatically infer synchronization.

An anchor row is `sourceID,sourceSeconds,programSeconds`; its fixed source-minus-program offset maps every switch to that original. Switch rows are `programSeconds,sourceID`, start at zero, increase strictly and stop before the exclusive program end. Decimal seconds permit up to three places. Two to32 distinct calibrated sources must already have clips in the timeline. Two to200 cuts must use at least two cameras; each cut lasts at least0.1 program second. Every derived window must fit its full original. Missing/duplicate/unknown anchors, stale duration catalogs, malformed/oversized worksheets, too-short cuts, out-of-bounds windows and unchanged proposals refuse without modifying the project. Windows are never silently shifted/clamped/dropped to fit.

All new cuts run at1×, regardless of existing clip speeds. Each camera uses its first current timeline clip as the appearance, volume, title, source-motion and caption/provenance template. Other clips' separate styles/cues are not merged. Only that first template's intersecting captions are retained with original source timestamps. The complete review identifies the supplying template index and retained cue count for every cut. Source motion stays source-anchored and clamps outside its old endpoints. New windows can use original footage outside the template's trimmed range. These rules are disclosed before input and again before replacement.

This is manual fixed-offset synchronization, without automatic audio/video alignment, camera-clock drift correction or codec frame-exact guarantees. Edge/audio fades repeat percut. The soundtrack keeps its settings/excerpt and starts at the new program beginning, changing prior music synchronization. Review says to preview/listen before export. Original files remain unchanged.

Input/review/apply reuse the owned batch-review path: exact project/source/account/foreground generation and soundtrack bindings, complete immutable proposal, one-use current dialog approval, dismissal/background/stale refusal and one project Undo. Input text and full mapping clear when their stages close. No automatic clipboard reading.
