# C126 — Inspect repeated source footage

Native video Project tools → Repeated source footage finds original-source intervals reused across different timeline clips, then lets the user explicitly jump to either occurrence. The inspector reads only project metadata. It does not decode media, compare pixels/files, delete footage or create an Undo edit. It can reveal partial overlaps even when clips differ in speed, title, crop, color, captions or audio; intentional reprises remain valid.

Every same-source pair is checked with half-open ranges: a shared interval exists when max(start) < min(end). Touching cuts do not overlap; even a one-millisecond source overlap is counted. Different source IDs are not compared, including duplicate files imported as separate sources. The report gives the exact pair count and keeps at most the100longest original-source overlaps, with deterministic earlier-clip tie order. It discloses omitted pair count and that multiple pairs may cover the same footage; it does not claim a unique duplicated-duration total.

A bounded priority queue retains only100pairs. Later candidates that cannot improve the length/clip-order ranking are skipped before allocating pair/occurrence objects. At1000clips,499500pairs are possible; all are counted without retaining an unbounded result list. Input uses existing project bounds and supported Int source-millisecond ranges. Pure current-state callbacks provide cooperative checks; the Activity uses lightweight admission checks during analysis and full project/source/session review validation afterward. This is synchronous metadata analysis; actual device responsiveness remains unverified.

Each result shows the original source ID and shared source range. The detail view shows both edited-playback positions and speed-adjusted shared lengths. Jump selects the chosen existing clip and seeks to the shared source start, updating the timeline playhead. Exact inspector ownership, current visible review, complete session/source state and project identity/snapshot are rechecked before navigation. Ownership is consumed and tracked reviews invalidated before selection/player changes. Retained Back/Jump callbacks cannot act on a successor. Empty reports are tracked too. Timeline clips/settings and originals remain unchanged.
