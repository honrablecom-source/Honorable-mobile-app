# C146 — Original-file ZIP with checksum manifest

**1 new experimental source workflow; 0 separate fixes; 0 scaffolding. Registered after source verification.** One outcome: Library selection → Create original archive packages one to twenty selected photo/video originals into a separate temporary ZIP, reviews ordered entry names, byte sizes and SHA-256 fingerprints, then explicitly shares only the prepared archive through Android's chooser. Each source byte is retained. Original metadata, including location/identifying fields, remains included; the review explicitly says this is not a sanitized copy. Nothing uploads automatically or changes originals.

Entries receive canonical ordered names (`originals/001.jpg`, etc.). A fixed allowlist maps provider-reported MIME labels to extensions; unknown labels become `application/octet-stream`/`.bin`. This labels the supplied data, not file-format validation. Source filenames, app IDs and URIs are excluded from `manifest.json`, which contains a format identifier, original-metadata-included flag, names, MIME labels, sizes and hashes. Embedded original metadata can still contain identifying text. SHA-256 verifies bytes, not authenticity or safety.

Streaming uses the existing read budget: strictly below 64 MiB per original and 256 MiB combined. The output cap is 257 MiB, allowing ZIP overhead. Level-zero ZIP deflate prioritizes bounded processing rather than smaller output. A failed destination latches failure so closing the ZIP cannot silently complete an earlier failed write; empty/missing/stalled/read-failing sources, cancellation and limits prevent success. The caller deletes failed temporary output. The completed archive has a separate digest and exact length, verified again before sharing.

Native preparation/share check current account, foreground Activity and exact ID/URI/type bindings. Request cancellation and checked 60-second deadlines bound work between provider calls; a physically blocked provider call need not cancel immediately. A separate one-use preview lease is cleared on pause/destroy/invalidate. Taking that lease before explicit chooser launch preserves the handed-off file through background cleanup. Android receives read-only access to the archive, without direct original URI grants. Cache output may expire and is not a durable backup; the chosen app must save a copy. Only this workflow's expired cache ZIPs are cleaned after one day.

JavaScript ties review/prepare/share to current owner and ordered selection, synchronously owns parent admission and refuses retained callbacks after close/reopen, same-tick selection change, source/order/account/background changes or unmount. Stale native results are released. Share consumes the lease even on failure, requiring a new preparation.
