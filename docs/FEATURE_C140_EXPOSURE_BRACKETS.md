# C140 — Blend aligned exposure brackets

Library → Select originals → Blend exposure brackets reviews two distinct, already aligned photos with equal orientation-corrected dimensions. Explicit Prepare creates a separate PNG; explicit Open transfers it into the existing protected-original local photo workspace. Both originals remain read-only and protected through the existing save/export URI contract. This is distinct from focus/temporal stacks: it computes a new color blend using exposure confidence rather than choosing a sharp/outlier-resistant source pixel.

For each pixel, rounded encoded8bit luma uses77/150/29 RGB weights. Confidence is256−abs(2×luma−255), so midtones receive higher weight than black/white. The squared confidence is weighted by source alpha. Alpha is a weighted mean; colors use alpha-correct weighted components with integer rounding and Long intermediates. A fully transparent bracket cannot darken the observed other pixel. Two fully transparent inputs produce canonical transparent black; hidden RGB is discarded there. Identical visible ARGB samples stay exact in the pure kernel and swapping inputs produces the same pixels. No source arrays are mutated.

This is an encoded8bit blend, not HDR reconstruction, color-space/profile management or a guarantee of recovered detail. Two clipped samples cannot provide missing information. Different exposure/white balance, camera motion and local weight changes can produce color shifts, ghosts or halos. There is no registration, optical flow, subject recognition or aesthetic guarantee. Review the actual PNG before opening. Native Bitmap/PNG/color conversion can differ from pure-array results and remains device-unverified.

The shared decoder applies readable EXIF orientation and uses the first decoded image for animation. Both corrected dimensions must match; a common power-of-two sample grid is at most1024pixels per edge and decoder rounding uses nearest-neighbor normalization.
