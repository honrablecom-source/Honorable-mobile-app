# Drawing image handoff ownership

November 7: **0 new user-facing features; 1 correctness integration fix; 0 app scaffolding. Source 93/500, batch 55 unchanged at this checkpoint.**

Use image / Use selected artwork now retains the exact drawing snapshot through rendering and FileReader completion. A changed document or replaced editor cannot send an old image. Rendering uses the existing bounded visible-artwork snapshot and excludes embedded editable-scene data. Preparation/bridge failures restore the captured selection only for the same document, retaining the editable draft. Orphan image callbacks are ignored when no image handoff is pending, so they cannot unlock an active print or SVG operation. Older native bridges that return undefined still work; current native false admission produces an actionable retry message. The existing one-argument bridge name is retained.

Native admission now requires the current foreground drawing and an idle shared export gate. One exact image operation owns preparation, launch and release. Pause cancels preparation and informs the renderer; destroy invalidates ownership. Old workers cannot launch or release later image/print/SVG work. A committed launch is a separate phase, so the expected activity transition is not cancelled as preparation. Background workers check ownership before decoding, creating/writing the private file and provider handoff; the UI checks again before launch. Bitmap recycling is in finally. Failed/stale work removes its own temporary file. Successful handoff retains the private copy for the photo editor. Originals are never written; the same guest-basic/read-only URI handoff and original-protection authority remain.

PNG input retains its existing 8 MiB/2048-edge bounds and now requires canonical Base64. The private encoded output is synced and must meet the final file-size budget before provider handoff. This is not a new photo encoder, arbitrary PNG security validator or successful-delivery guarantee. Paired native and drawing assets must be packaged together at the agreed batch boundary.
