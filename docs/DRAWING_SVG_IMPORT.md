# Import editable SVG artwork

November 8 — C099 adds **1 source workflow**: choose local SVG artwork, review it and insert a separate editable group. The file chooser, paste fallback, preview and insertion are one feature. Source total: 98/500; 60 outcomes beyond the 38-workflow batch baseline. A separate keyboard Undo correction is documented in [Drawing keyboard Undo](DRAWING_KEYBOARD_UNDO.md).

Projects → Vector artwork accepts a local SVG file or optional pasted SVG source. Preview converts supported solid-color paths and basic shapes into editable drawing paths. Insert places a new group beside visible artwork, keeps existing objects and their source copies, selects the result and brings it into view. One Undo removes the insertion; Redo, draft reopening and editable project transfer retain it. Existing object versions may advance for history capture; geometry, styles, IDs and source content stay intact.

Curves are sampled into polygonal paths. Outline caps and joins can differ from the original SVG; the review screen discloses that limitation. Plain paths, sharp or rounded rectangles, circles, ellipses, lines, polygons and polylines support bounded transforms and inherited solid paints. Both nonzero and evenodd fill rules preserve transparent holes. Signed winding partitions retain regions covered twice positively and once negatively. Fill holes use a connected path rather than separately rendered triangles.

Text, images, references, gradients, masks, clips, special effects, self-intersecting filled contours and unsupported opacity/compositing are refused explicitly. Artwork extending beyond the SVG canvas is refused instead of silently changing its clipping. Hidden shapes are omitted and reported. Limits include 64 KiB input, 128 visible shapes, 512 document nodes, 12 group levels, bounded commands/points/output paths, 500 total drawing objects and a 1 MiB draft. Object and draft limits reject the whole insertion.

The XML reader uses a detached document. Scripts, event handlers, document types, entities, external paints/resources and processing instructions are rejected before conversion. The imported artwork discards source IDs, titles, descriptions and metadata. Raw SVG is never inserted as active markup. Only sanitized geometry, paint and viewport data reaches a local Blob worker. That worker has a five-second deadline, clipping resource limits, request IDs, strict output validation and exactly-once termination/URL disposal. Cancellation, tool closure, source changes and hidden-document notifications invalidate previews. The selected file is read only; nothing is uploaded.

Android uses an explicit local/read-only Files intent. Unique request codes are persisted without wrapping within an activity history. Picker metadata waits for foreground before provider reading. Reading and UTF-8 decoding are bounded; chunks avoid splitting surrogate pairs. A matching client lease controls cached text and release. Cancellation, stale codes and duplicate results cannot release another operation. Recreation stores only code/pending metadata, never the selected URI or text, and does not restart reading automatically. Provider cancellation/deadlines are cooperative: an already-blocking provider call cannot be interrupted by these guards.

## Verified evidence

246 drawing tests pass: 208 retained plus 14 geometry, 5 reader, 9 worker-task and 10 file-transfer families. Chromium reader tests reject 20 unsafe/unsupported inputs and verify primitives, transforms, colors, visibility and metadata stripping. Actual production Blob-worker tests exercise computation, main-thread responsiveness, stale/cancel/deadline handling, malformed replies and cleanup. Synthetic worker faults are identified as such.

139 focused native host tests pass: 116 retained plus 23 new. The current DrawingActivity and eight helpers compile against API 34 with retained surrounding editor references. JDK streams exercise UTF-8/byte/zero-read/cancellation/chunk limits; constructor-free metadata tests exercise request ownership, foreground queuing and the actual Intent factory. They bypass Activity result-super and do not execute Android dialogs, providers, lifecycle delivery or JavaScript-interface marshaling. This is not a full current-module/configured SDK 37 build.

The actual editor browser flow selects a synthetic SVG file, previews and inserts it, verifies unchanged original geometry/style, strips private fixture metadata, exports real PNG/SVG and checks one-step Undo/Redo, reload and portable project content. The 429×429 transparent PNG has alpha 0 in the hole and alpha 128 in the red shell; SVG rasterization has the expected white-paper hole and pink shell. Native callback/chunk simulations verify cancellation, late/duplicate replies and matching busy release. Real canvas edits invalidate proposals; pending and ready previews are discarded on synthetic hidden-document events. Full-object and near-1 MiB drafts refuse atomically.

Insertion and Undo are directly exercised at 320×768, 390×844 and 844×390. Insert controls are at least 44 pixels high/wide; screenshots were reviewed. Browser runs have zero page errors and external requests. Retained shape-combine, photo-ownership and beginner finishing-guide regressions pass against the final bundle. The finishing guide now verifies seven project tasks, including Vector artwork, while retaining its previous routes and checks.

67 required Node tests and 8 drawing-asset tests pass. Drawing-only npm ci, isolated web compilation and the current 271-generated-file source/asset manifest pass. Esbuild warns that the parent React Native TypeScript configuration is unavailable; no mobile typecheck/lint/Jest acceptance is claimed. Local logs, source hashes and browser artifacts are under `.context/svg-import/`; disposable bundles and API JARs live in `/tmp`. The maintained editor regression is `creation-web/test/svg-import-preview.cjs`.

Actual Android Files/provider/grants/WebView/Blob-worker behavior, touch/accessibility/performance, screen recreation, photo-editor delivery, full native/APK and store acceptance remain unverified. Tracked Android drawing assets remain deferred to the owner's approximately 138-workflow build batch. These source/browser/API checks do not establish production readiness.

Direct pins `path-data-parser` 0.1.0 and `points-on-curve` 1.0.1 reuse existing installed transitive packages. No dependency package records were added or changed; only the root record gains the two direct pins. Exact pinned MIT notices are bundled alongside the existing polygon-clipping/Earcut notices. Upstream projects: [path-data-parser](https://github.com/pshihn/path-data-parser) and [points-on-curve](https://github.com/pshihn/bezier-points).
