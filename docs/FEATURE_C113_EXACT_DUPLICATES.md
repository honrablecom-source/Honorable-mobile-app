# C113 — Explicit selected-original duplicate-byte comparison

Library → Select originals → Check exact duplicates compares2–20 explicitly chosen originals using streamed SHA-256 and byte length. Results group fully read matching files and identify them using snapshotted display names/Library IDs. Nonmatching originals remain checked; skipped originals have explicit reasons. This is file-byte comparison, not perceptual similarity, semantic search, media decoding or deletion. Files, hashes and queries are never uploaded or persisted by this workflow.

One request reads at most256MiB per file and512MiB total, with a60-second checked deadline and64KiB buffer. These are strict read limits: a file reaching a limit before EOF is confirmed is skipped, even if its actual length equals that limit. Known over-limit lengths skip without reading data. Incomplete reads/digests, permission/provider failures, repeated zero-progress reads, mismatched declared lengths and failed stream closure never enter matching groups. Failed files are never treated as empty files. EOF-confirmed empty files can match as zero-byte files; no media-validity claim is made.

The bridge checks foreground/current account and exact native Library ID/URI/type bindings before IO and again before reporting. A single native request slot owns its cancellation ID. Cancel, account change, backgrounding, unmount, native host pause/destroy and module invalidation close owned streams and request provider cancellation. The worker releases only its own slot, including admission and executor failures. Provider IO may block or ignore cancellation; the deadline is checked between calls and is not a hard guarantee that blocked provider code returns within60seconds.

Reports describe the bytes delivered during this request. No saved integrity baseline, file-system snapshot or underlying-media lock is created. Source-content changes at an unchanged ID/URI/type cannot be detected independently of what the provider streams; known length mismatch is refused. Matching SHA-256 plus length is reported directly rather than claiming a second byte-for-byte verification pass.

The white mobile report shows counts, groups/hashes and skip reasons, with explicit Cancel/Close. Names remain in the JS view snapshot; native hashing receives only selected identities and a request ID. Account/background/close invalidates pending outputs and clears private results. A retained old Cancel cannot cancel/dismiss a successor. The report action appears only in selection mode; cancel keeps the selected originals for retry. A shared synchronous parent admission guard prevents a duplicate read and collection save/open from racing before React updates disabled states. Original media, catalog, index, ranking, credit ledger and project history are unchanged.
