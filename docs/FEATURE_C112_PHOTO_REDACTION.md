# C112 — Opaque privacy blocks in a separate photo copy

1 new user-facing source workflow;0 separate fixes. Browser checked; native/device acceptance pending.

Objects → Photo tools → Privacy → Privacy blocks accepts1–24 integer rectangles inside the8–1024-pixel embedded photo. Coordinates refer to the full original embedded raster before canvas crop, flip, rotation or opacity. Rectangles can overlap. Every covered RGBA pixel becomes0,0,0,255; no blur or translucent overlay is used. Output is a separate flattened PNG beside the source; original pixels and placement stay untouched, and one Undo immediately after insertion removes the copy.

The UI explicitly says the project still contains the unredacted original, that whole-drawing/project outputs can reveal it, and that only an inspected flattened redacted copy should be shared. It instructs selecting that new copy and using Projects → Image copies → Use selected artwork. This feature does not automatically detect faces/text or choose safe regions; source/photo metadata stripping uses the existing PNG re-encoding path. SVG/project exports intentionally retain both photo copies.

Input/region changes, hidden/Stop/teardown revoke the preview. Actual PNG encoding is guarded by the current editor/session generation and cancellation. Insert uses the existing quota-before-publication photo path and owned cancellation. The new explicit Cancel and Escape paths participate in the existing parent busy-click guard.
