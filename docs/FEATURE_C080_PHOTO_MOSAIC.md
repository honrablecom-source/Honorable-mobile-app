# C080 — Editable photo mosaics

**1 new experimental source workflow; 0 separate fixes/scaffolding.** Turn an embedded photo into grouped, individually editable colored triangles. Detail options are parameters of this one workflow. No full app build, Android drawing-asset refresh or device acceptance.

Drawing → Objects → a visible, unlocked, ungrouped photo → Photo mosaic. Choose Large triangles, Balanced or Small triangles and Preview. Review the result, then Insert editable mosaic or Keep original only. The new illustration appears beside the source as ordinary closed, filled line objects. Ungroup to edit individual triangles. One Undo removes the insertion; the original photo and existing protected artwork remain intact.

This uses the full embedded source before its displayed crop, rotation, flip or object opacity. The new mosaic starts upright and uses the source image's own pixel alpha. It is a stylized illustration, not an exact photo copy or edge-aware vector tracing. Triangles average encoded RGB by source opacity; hidden transparent RGB cannot tint them. Opacity is approximate per triangle, rounded to1–100%; empty facets are omitted. Fine features, transparency boundaries and antialiasing seams can change. Existing project and image/vector exports keep their usual behavior; there is no new project schema or image file dependency for the triangle objects.

## Implementation

`photo-mosaic.mjs` builds a deterministic jittered mesh with the exact source rectangle on its boundary, then uses pinned Delaunator5.1.0 for triangulation. Long-edge detail is bounded to3–12 cells and reduced on very small photos. Sources use existing embedded-copy limits of8–1024 pixels per side. At most288 triangle objects are generated; narrow photos create fewer. Pixel-center membership determines each triangle's alpha-weighted average; subpixel facets without pixel centers use their centroid pixel. An empty result is refused.

The browser yields after small batches of eight facets and checks the captured drawing/source guard before decoding, after decoding, before work, between facets/batches and before publication. Closing the component invalidates its request. Applying rechecks the same editor instance, bounded document snapshot, exact embedded source data and busy state. The existing commit path validates the whole insertion against500objects and the draft byte budget before updating the scene; it never silently drops triangles to fit. Existing source photos, crop/rotation/flip/opacity, bindings, file bytes and other objects are retained.

`PhotoMosaicTool` provides the local source/triangle preview, detail invalidation, explicit insertion/Cancel and progress/error feedback in Noble's existing white/black workspace. Actual media-derived colors appear only in the artwork. The group is selected after insertion; existing image-copy/project transfer/SVG paths handle it. No network operation, media query logging, AI service, billing or search-ranking change.

Delaunator5.1.0 was already present in the drawing lockfile. Its new direct pin changes only the root dependency declaration; all resolved packages remain identical. Delaunator's ISC notice and robust-predicates3.0.3's Unlicense text are copied unchanged into the drawing THIRD_PARTY assets. No runtime package was newly resolved/downloaded for the feature. Upstream reference: https://github.com/mapbox/delaunator . Browser fonts/notices continue to be bundled locally.
