# C089 — Named editable versions of an original photo

One new experimental source workflow: keep several named editing alternatives for an imported photo and reopen them without replacing its single saved-edit slot. Created-image workspaces retain their existing canvas project workflow.

In the native photo editor, open **Editable project → Saved photo versions**. Save current settings under a new name, choose a version to review and open, or delete an unused version. A changed open adds one existing photo Undo entry; identical settings do not add another. Deletion removes settings only, with an in-shelf Undo that refuses intervening shelf changes. Save never silently overwrites a name.

Each private guest/account-and-original shelf holds at most 20 versions and 512,000 encoded bytes; large edits may fill it earlier. Names use 1–40 UTF16 units, with normalized case-insensitive uniqueness. Records reuse the existing encrypted SecureAccountStore preserving-read path. Strict bounded native project/catalog codecs, hashes and readback reject damaged, unsupported or mismatched records rather than treating them as empty. Process-local serialization protects same-process writers; it is not a cross-process transaction. A readback error or cancellation can follow an already committed write; reopening the shelf reveals its state.

Saving and opening hash the actual readable original bytes through the existing capped fingerprint routine. Opening requires matching original bytes, owner and URI. If the original changes, versions remain stored and deletable, but their edits cannot be opened against the changed bytes. Original media is neither copied nor uploaded. Captions, objects and protected source references are editable metadata inside the encrypted record. Primary source access uses the existing durable-read transaction; this does not guarantee future provider access. Provenance unions with the current protected sources before commit, retains protection through photo Undo, and refuses the existing 16-source limit instead of dropping originals.

A dedicated worker owns record and fingerprint I/O. Foreground/source/model/session/generation checks and owned dialog tokens prevent stale approval. Pause/destroy closes the shelf and cancels its worker; only its own busy state is released. An operation already writing may finish. Preview success is reported separately from metadata application.
