# C094 — Import subtitles timed to the edited video timeline

One new experimental source workflow: import an SRT timed to the entire edited playback project, mapping its cue intersections back onto each clip's original-source timestamps. Existing selected-clip SRT import remains available and still interprets its timestamps against that clip's original source with a 200-cue limit. This is timeline subtitle placement, not transcription or translation.

Open **Timed captions → Import SRT for edited playback timeline**. Apply or reset any pending trim selection first so the stored project timeline matches its playback/export timing. The disclosure explains replacement and limits, then the native Files picker chooses a document. Reading and mapping run locally. A review reports input cues, mapped source fragments, changed clips, existing caption count and precision adjustments, with the first eight fragments and an explicit remainder count. Approve replaces all project captions in one existing Undo/Redo step. Titles, music, trims, clip order, speeds, visual settings and original media remain. Preview failure is reported separately from metadata application.

Mapping clips each playback cue to every intersected edited clip, handles repeated and different source clips independently, and inverts trim/speed using integer half-speed units. Native captions use source milliseconds: each mapped boundary stays between floor/ceiling of its ideal source point, with ordered nonoverlap and at least one source millisecond per fragment. Shared boundaries remain ordered; fractional cut fragments retain their text. If those requirements cannot all fit, the whole import rejects rather than dropping text or creating overlaps. Boundary adjustment is at most one source millisecond (at most two playback milliseconds at 0.5x). A final SRT millisecond may be clipped by less than one millisecond to the true project end. These are metadata timing guarantees, not frame/audio sync or playback proof.

The existing strict UTF8/SRT parser is reused with a separate whole-playback entry: up to 128,000 raw bytes, 1000 input cues, 240 UTF16 units/three lines per cue and 64,000 input text bytes. Original clip import remains 200 cues. Mapping still enforces 200 per clip, 1000 total mapped fragments, 64,000 mapped text bytes and the existing recoverable draft payload budget; crossing cuts can therefore exceed limits even when input fits. Timing remains within native source bounds and the parser's Int.MAX_VALUE millisecond timeline limit. Empty/invalid encoding, malformed/overlapping/out-of-range cues and invalid document references reject without changing captions. Prepared models/cue lists are defensive and immutable.

A dedicated owned controller holds the editor's import busy state across disclosure, picker, read and review. The expected picker transition may pause the Activity; a returned URI/flags waits until foreground before any provider read. Reads/reviews cancel on pause/destroy, with single-use result phases and stale dialog tokens. The read-progress dialog also offers Cancel without leaving the editor; cancel/keep notices leave clear status. Current Activity/project/clip-list/soundtrack/source catalog/mode/session/range/recovery checks prevent stale approval. Read workers compare target identity and the small imported-video catalog without repeatedly traversing source history or decrypting the account store. Full authorized snapshot and source-history catalog comparisons occur at UI admission/review/commit. Only the owning controller may release its busy flag. Recreation does not persist/replay an unfinished import.

The document is read-only, bounded and checked through the existing native descriptor identity policy. Persistent READ access is retained only on explicit replacement approval, with offered grant flags or existing read ownership. Existing grant commit rollback revokes only newly acquired access after a failed metadata commit; grants already owned by another project remain. Imported document URI provenance is retained in clip state/history, keeping the existing original-protection policy. No WRITE grant, media upload, subtitle upload, personal query logging, cloud transcription/translation call, new dependency or source-file write is introduced. Provider reads may be noninterruptible; cancellation is cooperative and cannot promise immediate descriptor release. Android/provider grant persistence and later availability remain unverified.
