# C110 — Private named Library collections

Library → Private collections saves the current 1–20 selected originals under a name, separately for each signed-in account on this device. Open a saved collection to filter loaded Library items by the saved ID, URI **and** media type; filename/type filters remain available. Load more can reveal other saved members. The view reports how many saved originals are loaded and distinguishes loaded coverage from file availability. Show all originals exits the collection view. Collection order follows Library date order; original selection order remains in stored references.

The shelf supports up to20 named collections, bounded names and a400,000-byte metadata payload. Case/NFKC-equivalent duplicate names, repeated IDs/URIs, invalid media bindings, invalid Unicode and quota overflow refuse before writing. Saving snapshots selected identities and rechecks current native Library records under the store transaction; a reused ID with a changed URI/type cannot substitute another original. Contents at an unchanged ID/URI/type are **not fingerprinted** and changes to those contents cannot be detected by this workflow.

Remove collection opens a separate explicit review and deletes only that collection's saved references. Originals and other collections stay. Removal has no Undo and is disclosed. No media is read, copied, deleted, uploaded or shared by collection operations.

The native bridge captures the existing private account namespace, checks foreground/activity/session ownership, and runs off the UI thread. The new record reuses existing Android Keystore/AtomicFile encryption under a separate owner-hashed filename. The binary payload also binds its owner and version. Unreadable or oversized records propagate errors and remain preserved; saving never silently resets corrupt metadata. Transactions merge the latest record under one shared lock. Session checks immediately precede storage writes; backgrounding/cancellation cannot promise rollback after a write has committed.

The React Native shelf opens only on explicit request. Exact native-owner and shelf-object checks prevent old or replaced shelf rows from opening/removing stale references. Account changes, backgrounding, closing and unmounting invalidate pending results and clear private details. Parent Library operations are disabled while collection work is pending; duplicate taps are refused synchronously. Failed saves retain input for retry. Collection views never filter or reorder the native search engine.
