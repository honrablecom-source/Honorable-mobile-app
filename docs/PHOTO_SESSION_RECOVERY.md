# Keep unresolved photo-session recovery

Zero new user-facing features; one core recovery correctness/usability fix. Source count remains85/500, batch47 beyond38 at this checkpoint.

The native photo editor previously turned a failed saved-session decode into null, continued with a source/default edit and later saved that replacement over the incoming recovery state. After normal editor source/access-mode admission, it now retains an independent copy of the exact incoming photoSession metadata until the validated model is applied or the owner explicitly discards recovery. Missing, mismatched or unavailable scope, damaged/truncated/future/trailing data, source-load failure and retry failure never become an empty recovered edit. The existing strict codec still bounds decoding to64KiB; retained input is not repaired or migrated on failure.

A visible recovery panel explains that editing/saving is paused and offers **Retry recovery** and **Start original**. While unresolved, changes, history navigation, AI, project storage and export are guarded; the preview shows the source rather than implying the old edit was recovered. Retry uses the current loaded scope, or asks Android to recreate/reload the editor when the source bitmap is unavailable. A failed retry keeps the same payload. If source/session access is still unavailable, reopening/authentication/access recovery may be needed.

Valid model application prepares replacement Undo/Redo collections before committing edit/history/compare/tool state; only then does it consume recovery. History is replaced rather than appended on repeated preparation. UI selection/preview follows model application separately. Existing valid pending-export context remains live: a picker cancellation/result received during source loading is not overwritten from the older recovery snapshot. A separate saved-state invalidation marker prevents a handled/cancelled picker from being revived merely because exact raw metadata is retained. When a pending export cannot be associated with a valid live context, choose Export again; no stale destination is automatically written while recovery is pending.

Start original requires a current owned review with the same retained recovery identity, foreground generation and full current photo-close snapshot. Keep recovery/cancel leaves bytes untouched. Pause/destroy dismisses and invalidates the review. Confirmed discard resets only in-memory edits/history/pending export and deferred starting tools. Existing saved projects, source URI and protected original list remain. It is irreversible within this editor session. If no bitmap is available, the UI asks the owner to reopen the original after discarding.

The raw-first saved-state branch runs before fresh scope/codec encoding, retaining bytes even when current scope cannot be read. Photo Close/Back also recognizes unresolved raw recovery and reviews leaving it. This is framework saved-instance-state retention, not a durable backup or sync service: actual Parcel/Binder persistence, process death, memory pressure and OS saved-state size limits are unverified. No promise is made that damaged metadata can be recovered. No raw pixels, personal media or queries are uploaded or added to storage by this change.
