0 new features; 1 core approval correctness fix; 0 scaffolding. This does not add to the 88 source workflows or batch 50 at this checkpoint.

Previously, paused native photo Reset and Delete saved edits could enter dialog construction. Reset checked the edit value, source and scope at approval but had no owned token or foreground generation. Saved-edit deletion called the generic project operation at button press, which could select a later current photo/session. Its worker did not require the original foreground generation.

Both controls now require foreground, idle/loaded editor admission with no pending picker/destination. Review captures the full existing PhotoCloseState and scope/access mode: edit and history identities, source, protected originals, pixels, recovery, pending work, canvas state, generation and revision. Approval requires the same owned token and snapshot. Replaced callbacks return without closing a newer review. Cancel/dismiss clear only their own review; pause/destroy invalidate and dismiss it.

Reset uses the existing metadata commit: one photo Undo entry restores the previous edit, Redo is cleared, and original-source protection remains. Preview failure is reported separately. Delete still removes only the single saved-edit slot; originals, current edits and named versions remain. Deletion and Restore workers require matching foreground generation, while the existing background Save policy is retained. Store checks are cooperative; this is not a transactional cancellation/rollback guarantee once deletion has begun.
