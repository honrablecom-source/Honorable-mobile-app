# C144 — Local photo EXIF privacy audit

One experimental source workflow: Library selection → Inspect photo privacy reads one to twenty original photos locally, reports presence of eighteen supported EXIF location, camera-owner/body-serial, descriptive and timestamp fields, then optionally selects only location-flagged originals. No EXIF values appear in the report. Originals are read-only; this workflow removes nothing and uploads nothing.

A report with no listed fields is not a privacy guarantee. Lens serial numbers, XMP, filenames and visible image content are explicitly unchecked. AndroidX ExifInterface 1.4.2 declares a lens-serial constant but omits that tag from its read table; the actual-parser fixture caught this limitation before registration. Lens serial was removed from the advertised whitelist rather than treating an unread tag as absent. Invalid/unavailable inputs can report Unknown; absence of supported fields never means metadata-free.

Native reads reuse exclusive Library admission, ID/URI/type and account/foreground guards, cancellation, 64 MiB per stream/256 MiB total budgets, a checked 60-second deadline and 96 MiB initial heap headroom. Provider calls can remain blocked until returning. JavaScript binds reports and retained callbacks to current owner, exact ordered original bindings and selection references. Cancel, background, owner/selection/source changes and unmount suppress late publication. Focusing location results changes only the current selection and validates its original subset again.
